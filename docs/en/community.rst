Contributing, support and license
=================================

Contributing
------------

The :download:`contribution guide <../../CONTRIBUTING.md>` owns the contributor
workflow, local checks and pull request expectations. For changes to experiments
or adapters, also read :doc:`development`. Update both documentation languages
and the matching Python examples together.

Support and bug reports
-----------------------

Start with :doc:`troubleshooting`, :doc:`devices` and :doc:`validation`.
The :download:`support guide <../../SUPPORT.md>` explains how to report an SDK
problem through the source repository's issue tracker. Use its
:download:`bug report template <../../.github/ISSUE_TEMPLATE/bug_report.md>` and
include SDK/Python versions, operating system, a minimal reproduction and
sanitized logs. Include device type, firmware and experiment key for device
problems. Keep hardware service and calibration questions with the equipment's
support provider.

Security reporting
------------------

Follow the :download:`security reporting guide <../../SECURITY.md>` for suspected
vulnerabilities. Use the repository's private reporting mechanism when available
or an existing private maintainer contact. Keep credentials, full session IDs and
sensitive traffic out of public issues.

License and release history
---------------------------

The Python sources use GPL-3.0-only; the complete text is in
:download:`LICENSE.txt <../../LICENSE.txt>`. Release notes are maintained in
:download:`CHANGELOG.md <../../CHANGELOG.md>`. Hardware and platform verification
evidence is recorded separately in :doc:`validation`.
